# Astra

> **Хочешь, чтобы друзья заходили просто по ссылке, без VPN?** Арендуй недорогой VPS в России и выполни одну команду —
> см. **[docs/DEPLOY.md](docs/DEPLOY.md)**:
> ```bash
> curl -fsSL https://raw.githubusercontent.com/saidovkebed-lang/sozvon/main/deploy/install.sh | sudo bash
> ```

Свой маленький «Discord» для друзей, который работает у вас дома. Один человек запускает сервер у себя
на компьютере, остальные открывают его в браузере, по локальной сети или через VPN-оверлей.

Что умеет:

- серверы (группы) с приглашением по 8-символьному коду, текстовые и голосовые каналы;
- чат в реальном времени: история, вложения (картинки и файлы до 100 МБ), удаление сообщений;
- **личные сообщения** с участниками своих серверов: только переписка — текст, фото, видео, файлы (без звонков);
- **«Входящие»** (колокольчик): упоминания `@ника`, `@everyone` и личные сообщения в одном месте;
- **push-уведомления**: личные сообщения и упоминания приходят, даже когда Astra закрыта —
  в браузере на компьютере и на телефоне (на iPhone — у установленного на главный экран приложения);
- **роли и права, как в Discord**: владелец создаёт роли (цвет, отдельная группа в списке участников),
  раздаёт права (управление сервером/каналами/ролями, кик, бан, mute, перемещение в голосе, музыка…),
  закрывает каналы для отдельных ролей; иерархия ролей соблюдается;
- **профиль «Нитро бесплатно»**: аватар и баннер (в том числе анимированные GIF), «Обо мне», местоимения,
  статус (в сети / не активен / не беспокоить / невидимый) и свой статус с эмодзи, тема профиля;
- счётчик пинга до сервера и качества голосового соединения;
- приложение для ПК (Windows/Linux) — страница `/download` вашего сервера;
- голосовые каналы, камера и демонстрация экрана (WebRTC, P2P между участниками);
- **DJ Бот**: включает музыку в голосовом канале по командам из чата (`!play …`), у всех слушателей
  она играет синхронно. Понимает ссылки на YouTube (видео и плейлисты), Spotify (плейлисты, альбомы,
  треки) и SoundCloud, ищет по названию — подробно в **[docs/MUSIC.md](docs/MUSIC.md)**.

## Требования

- **Node.js 20 или новее** (`node -v`).
- Современный браузер: Chrome, Edge, Firefox, Яндекс Браузер. Safari тоже работает, но хуже.
- Необязательно: [`yt-dlp`](https://github.com/yt-dlp/yt-dlp) не старше ноября 2025 (и `ffmpeg`) — для музыки
  по ссылкам YouTube/Spotify/SoundCloud и поиска по названию. На VPS (`deploy/install.sh`) ставится сам.
- Желательно: `ffmpeg` (и `ffprobe`) — аватары, баннеры и иконки серверов обрезаются до нужного размера,
  у анимированных GIF/APNG сохраняется анимация и делается статичный кадр. Без ffmpeg картинки
  сохраняются как есть, без обрезки.

## Установка

```bash
npm install
```

## Запуск

Сервер:

```bash
npm start
```

При старте сервер печатает адреса, по которым к нему можно зайти, например:

```
🎧 Astra запущена! Адреса для входа:
  https://localhost:3000
  https://192.168.1.42:3000
```

Музыкальный бот запускается **во втором окне терминала** (сервер при этом должен работать):

```bash
npm run bot
```

Бот сам находит свой токен (`data/bot-token.txt`, его создаёт сервер) и переподключается, если сервер
перезапустили. Остановить сервер или бота: `Ctrl+C`. Перед выходом сервер сохраняет данные на диск.

## Как друзьям подключиться

### В одной сети (Wi-Fi или роутер)

Друзья открывают адрес вида `https://192.168.x.x:3000` из списка, который напечатал сервер.
Если не открывается, разрешите Node.js во входящих подключениях брандмауэра Windows
(или откройте порт 3000).

### Через интернет

Проще всего поставить всем одну и ту же программу виртуальной сети:

- **Radmin VPN**: создайте сеть, друзья к ней присоединяются;
- **ZeroTier**: общая сеть по Network ID;
- **Tailscale**: все входят в один tailnet (или вы делитесь машиной).

Потом друзья открывают `https://<VPN-IP-вашего-ПК>:3000`. VPN-адрес тоже будет в списке при старте,
если VPN был включён до запуска сервера. Сертификат сам пересоздаётся под новые IP при следующем старте.

Пробрасывать порт на роутере можно, но небезопасно: сервер рассчитан на своих.

### Предупреждение о сертификате

Микрофон, камера и демонстрация экрана в браузере работают только по HTTPS. Поэтому сервер
при первом запуске создаёт **самоподписанный сертификат** (`data/certs/`). Браузер его не знает и
покажет предупреждение «Подключение не защищено». Это нормально:

- **Chrome / Edge / Яндекс:** «Дополнительные» → «Перейти на сайт … (небезопасно)».
- **Firefox:** «Дополнительно…» → «Принять риск и продолжить».
- **Safari:** «Показать подробности» → «посетить этот веб-сайт».

Подтверждать нужно один раз на каждом устройстве и для каждого адреса.
Открывайте именно `https://…`. Если зайти по `http://` на тот же порт, страница не загрузится.

## Музыка

Подробная инструкция для пользователей и администратора: **[docs/MUSIC.md](docs/MUSIC.md)**.

- **По ссылке:** `!play <ссылка>` — YouTube (видео, Shorts, `youtu.be`, `music.youtube.com`, плейлисты),
  Spotify (`open.spotify.com/playlist|album|track/…`, `spotify:…`), SoundCloud (трек или сет).
  Плейлист сразу встаёт в очередь, а каждый трек скачивается перед воспроизведением (следующий —
  заранее). Скачанное кэшируется в библиотеке, повторно не качается.
- **Spotify:** звук из Spotify не скачивается (DRM). Бот берёт названия треков (через Spotify Web API,
  если заданы `SPOTIFY_CLIENT_ID`/`SPOTIFY_CLIENT_SECRET`, иначе с публичной embed-страницы) и ищет
  каждый трек на YouTube/SoundCloud со сверкой длительности (±15 с).
- **По названию:** `!play исполнитель — песня` ищет сначала в библиотеке, потом на YouTube/SoundCloud.
- **Свои файлы:** библиотека бота лежит в папке **`data/music`**. Можно просто положить туда mp3, m4a, ogg,
  opus, wav, flac или webm: сервер подхватит их сам и прочитает название и исполнителя из тегов
  (без тегов используется имя файла, формат «Исполнитель - Название.mp3» тоже понимается).
  Или кнопка «Библиотека» в плеере → загрузить файл (до 50 МБ) или вставить прямую ссылку на аудио.
- Для ссылок и поиска нужен `yt-dlp` (путь — `YTDLP_PATH`, по умолчанию `yt-dlp` из PATH). Установка:
  `winget install yt-dlp`, `brew install yt-dlp`, `pipx install "yt-dlp[default]"` или бинарь с GitHub.
  Для YouTube yt-dlp использует Node.js, который у вас уже есть. Если yt-dlp нет, работают
  библиотека и прямые ссылки на аудио.
- **Плейлисты и автоплей:** у каждого сервера свои сохранённые плейлисты («Библиотека» → «Плейлисты»,
  `!playlist …`) и переключатель «Автоплей» в плеере (`!autoplay on`) — см. [docs/MUSIC.md](docs/MUSIC.md#плейлисты).
- С российского сервера YouTube может требовать cookies или не открываться — тогда помогают
  SoundCloud, `YTDLP_COOKIES`, `YTDLP_PROXY`. Проверка с VPS: `sudo bash /opt/sozvon/deploy/music-check.sh`.

### Команды бота

Пишите в любом текстовом канале. Для команд управления нужно сидеть в голосовом канале.

| Команда | Что делает |
|---|---|
| `!play <запрос>` | ищет в библиотеке по названию, исполнителю или имени файла (регистр не важен), не нашёл — на YouTube/SoundCloud; включает или ставит в очередь |
| `!play <ссылка>` | YouTube/SoundCloud/Spotify: трек или весь плейлист в очередь; прямая ссылка на аудио — скачивает в библиотеку |
| `!play` | продолжить после паузы |
| `!pause` / `!resume` | пауза / продолжить |
| `!skip` | следующий трек |
| `!np` | что сейчас играет |
| `!queue` | очередь |
| `!remove <n>` | убрать трек номер n из очереди |
| `!move <откуда> <куда>` | переставить трек в очереди |
| `!seek <1:23 \| 83 \| +10 \| -10>` | перемотать текущий трек (или ползунком в плеере) |
| `!shuffle` | перемешать очередь |
| `!playlist <название>` / `!pl` | включить сохранённый плейлист сервера; `!playlist shuffle <название>` — вперемешку |
| `!playlist list` / `!playlist save <название>` | плейлисты сервера / сохранить текущую очередь как плейлист |
| `!autoplay on \| off` | автоплей: когда очередь кончится, бот подберёт похожие треки (радио-микс YouTube) |
| `!stop` | остановить, очистить очередь и выйти из канала |
| `!leave` | выйти из голосового канала |
| `!help` | список команд |

На каждом сервере бот играет в одном голосовом канале. Если очередь закончилась, через 2 минуты тишины
бот уходит. Когда из канала выходят все люди, бот тоже выходит. Если бот не запущен, на `!`-команды
сервер отвечает подсказкой «Музыкальный бот не запущен. Запустите: npm run bot».
Звук бота не передаётся по WebRTC: каждый браузер сам проигрывает файл с сервера в нужной позиции.
Громкость музыки настраивается слайдером в плеере.

## Переменные окружения

| Переменная | По умолчанию | Описание |
|---|---|---|
| `PORT` | `3000` | порт сервера |
| `HOST` | `0.0.0.0` | интерфейс для прослушивания |
| `HTTPS` | `1` | `HTTPS=0` включает обычный HTTP (голос и экран тогда работают только на `localhost`) |
| `DATA_DIR` | `./data` | каталог данных: `db.json`, `uploads/`, `music/`, `media/`, `downloads/`, `certs/`, `bot-token.txt` |
| `PUSH_SUBJECT` | `PUBLIC_URL` | контакт владельца сервера для push-сервисов (VAPID): `mailto:вы@почта` или `https://ваш-сайт`. На VPS из deploy подставляется адрес сервера |
| `UPLOAD_LIMIT_MB` | `100` | максимальный размер вложения в чате, МБ (за nginx из deploy — не больше 100) |
| `FFMPEG_PATH` / `FFPROBE_PATH` | `ffmpeg` / `ffprobe` | пути к ffmpeg/ffprobe для аватаров и баннеров |
| `SOZVON_NO_FFMPEG` | — | `1` — не использовать ffmpeg (картинки сохраняются как есть) |
| `SOZVON_ANIM_FORMAT` | `gif` | формат анимированных аватаров/баннеров: `gif` или `webp` (анимированный WebP меньше, но ffmpeg 6 не умеет его читать) |
| `ICE_SERVERS` | `[{"urls":"stun:stun.l.google.com:19302"}]` | JSON-массив STUN/TURN-серверов для WebRTC |
| `BOT_SERVER_URL` | `https://localhost:3000` | (бот) адрес сервера |
| `BOT_TOKEN` | из `DATA_DIR/bot-token.txt` | токен бота. Если задан у сервера, его же нужно задать боту |
| `BOT_IDLE_MS` | `120000` | (бот) через сколько миллисекунд простоя бот выходит из канала |
| `YTDLP_PATH` | `yt-dlp` | путь к yt-dlp |
| `YTDLP_COOKIES` / `YTDLP_PROXY` | — | cookies.txt для YouTube / прокси только для скачивания музыки |
| `YTDLP_TIMEOUT_SEC` | `300` | максимум на скачивание одного трека (поиск и плейлисты — `YTDLP_META_TIMEOUT_SEC`, 90) |
| `MUSIC_SEARCH_SOURCES` | `youtube,soundcloud` | где и в каком порядке искать треки |
| `MUSIC_PLAYLIST_LIMIT` | `100` | сколько треков брать из плейлиста |
| `MUSIC_DURATION_TOLERANCE` | `15` | допуск длительности при поиске треков Spotify, секунд |
| `SPOTIFY_CLIENT_ID` / `SPOTIFY_CLIENT_SECRET` | — | ключи Spotify Web API (необязательно) |
| `SPOTIFY_PROXY` | — | HTTP-прокси только для Spotify (из РФ Spotify недоступен); свой VPN подключается через `sudo bash /opt/sozvon/deploy/vpn-proxy.sh` |
| `SPOTIFY_EMBED_BASE`, `SPOTIFY_API_BASE`, `SPOTIFY_ACCOUNTS_BASE` | адреса Spotify | для тестов: подмена на фейковый сервер |

Все музыкальные настройки — в [docs/MUSIC.md](docs/MUSIC.md#все-настройки-музыки).

Пример для Windows PowerShell: `$env:PORT=4000; npm start`. Для bash: `PORT=4000 npm start`.
Если сервер запущен на другом порту, боту нужен тот же адрес: `BOT_SERVER_URL=https://localhost:4000 npm run bot`.

## Где хранятся данные

Всё лежит в `data/`. Пользователи, серверы и сообщения хранятся в `data/db.json`: запись атомарная,
каждое изменение сохраняется на диск примерно через 0,3 с. Вложения лежат в `data/uploads/`,
музыка в `data/music/`, аватары/баннеры/иконки — в `data/media/`, файлы приложения для ПК — в
`data/downloads/` (описание релиза — `data/app-release.json`). Ключи push-уведомлений создаются
при первом запуске в `data/vapid.json`: никому их не показывайте и не удаляйте — с новыми ключами
у всех придётся заново включить push в настройках. Для резервной копии достаточно скопировать папку `data/`;
на VPS копии делаются автоматически каждую ночь (`deploy/backup.sh`, шифрованная отправка в свой Telegram — по желанию),
см. [docs/BACKUP.md](docs/BACKUP.md).

При первом запуске новой версии база обновляется автоматически: у старых серверов появляется роль
@everyone с правами по умолчанию, владелец остаётся владельцем, у пользователей — пустой профиль.
Перед этим рядом сохраняется копия `db.json.pre-v3-<время>`.
Пароли хранятся только в виде bcrypt-хэша. В каждом канале хранятся последние 2000 сообщений.

## Ограничения

- Голос и видео идут по **mesh-схеме**: каждый участник шлёт поток каждому. Комфортно примерно
  **до 6–8 человек в одном голосовом канале**. С демонстрацией экрана или камерами лучше меньше:
  всё упирается в исходящий канал интернета у того, кто стримит.
- Если у двух участников строгий NAT, P2P-соединение может не установиться без TURN-сервера.
  Внутри Radmin VPN, ZeroTier или Tailscale обычно всё работает. Свой TURN подключается через `ICE_SERVERS`.
- Сертификат самоподписанный, поэтому браузер предупредит при первом входе (см. выше).
- Сервер рассчитан на компанию друзей: восстановления пароля нет. Удалить сервер и передать
  владение может только владелец; остальное — по ролям и правам, которые он раздаёт.
- Если длительность трека неизвестна (битый файл), бот не переключит его сам: нужен `!skip`.
- Музыка из интернета — для личного некоммерческого использования; звук Spotify не скачивается (только
  метаданные), треки ищутся на YouTube/SoundCloud и иногда находится не та запись.
