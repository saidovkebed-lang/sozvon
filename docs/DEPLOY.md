# Созвон на своём сервере: друзья заходят по ссылке, без VPN

Эта инструкция для тех, кто никогда не настраивал сервер. Вы арендуете маленький сервер (VPS)
в России, вставляете **одну команду**, и через 5 минут получаете ссылку вида
`https://chat.example.ru`. Друзья открывают её в браузере, им ничего не нужно устанавливать.

Что делает установка сама:

- ставит всё нужное: Node.js, веб-сервер nginx, TURN-сервер coturn (через него идёт голос,
  когда напрямую соединиться не получается), certbot (бесплатный сертификат HTTPS);
- получает настоящий сертификат Let's Encrypt, поэтому браузер не покажет предупреждений,
  а микрофон, камера и демонстрация экрана работают;
- запускает Созвон и музыкального бота как службы: они сами поднимаются после перезагрузки сервера;
- настраивает файрвол и проверяет, что всё отвечает.

---

## Шаг 1. Арендуйте VPS

Подойдёт любой российский провайдер VPS: Timeweb Cloud, Beget, Selectel, REG.RU и другие.
При заказе выберите:

| Параметр | Что выбрать |
|---|---|
| Операционная система | **Ubuntu 24.04** (подойдут также Ubuntu 22.04 и Debian 12) |
| Процессор / память | **1 vCPU, 1–2 ГБ RAM** (на 1 ГБ работает, с 2 ГБ запас) |
| Диск | от 10 ГБ (больше, если будете загружать много музыки и файлов) |
| Сеть | **публичный IPv4-адрес** (обычно включён; если это отдельная опция, отметьте её) |
| Расположение | **Россия** (Москва, Санкт-Петербург и т.п.), ближе к вам и друзьям |
| Тип | обычный VPS / облачный сервер (KVM). Не «хостинг сайтов» и не контейнер |

Стоит это обычно несколько сотен рублей в месяц. Безлимитный трафик или хотя бы 1–2 ТБ в месяц
и канал от 100 Мбит/с хватят с большим запасом.

После создания сервера провайдер покажет (или пришлёт на почту) **IP-адрес** (например `81.200.10.20`)
и **пароль root**. Они понадобятся на следующем шаге.

## Шаг 2. Подключитесь к серверу

Нужно открыть «командную строку» сервера. Вариантов два, выберите удобный.

**Вариант А: веб-консоль в панели провайдера.** У большинства провайдеров на странице сервера есть
кнопка «Консоль» / «VNC» / «Открыть терминал». Нажмите её, введите логин `root` и пароль.
(При вводе пароля символы не отображаются, это нормально.)

**Вариант Б: со своего компьютера по SSH.**

- **Windows 10/11:** нажмите Пуск, наберите `PowerShell`, откройте его и введите
  (подставьте свой IP):
  ```
  ssh root@81.200.10.20
  ```
  На вопрос `Are you sure you want to continue connecting` напишите `yes` и нажмите Enter,
  потом введите пароль (его не видно при вводе) и нажмите Enter.
- **macOS / Linux:** откройте «Терминал» и введите ту же команду.

Получилось, если вы видите строку вроде `root@my-server:~#`.

> Если провайдер дал пользователя не `root`, а, например, `ubuntu`, подключайтесь под ним:
> команда установки ниже начинается с `sudo`, этого достаточно.

## Шаг 3. Установите Созвон одной командой

Скопируйте команду целиком, вставьте в окно сервера (в PowerShell: правой кнопкой мыши)
и нажмите Enter:

```bash
curl -fsSL https://raw.githubusercontent.com/saidovkebed-lang/sozvon/main/deploy/install.sh | sudo bash
```

Установка идёт 3–5 минут. В конце вы увидите рамку со ссылкой:

```
=====================================
    https://81-200-10-20.sslip.io
=====================================
Созвон установлен!
```

Это и есть адрес вашего Созвона. Если вместо рамки появилась ошибка, найдите её в разделе
[«Частые проблемы»](#частые-проблемы): обычно её исправляют в панели провайдера, после чего
команду установки нужно запустить ещё раз. Повторный запуск безопасен, ничего не сломает
и данные не сотрёт.

> **Про адрес `…sslip.io`.** Если у вас нет своего домена, установщик берёт бесплатный адрес
> на основе IP сервера. Это работает сразу, но сервис sslip.io находится за рубежом и иногда
> бывает недоступен. **Свой домен .ru надёжнее** (см. [«Свой домен»](#свой-домен)).

## Шаг 4. Пользуйтесь

1. Откройте ссылку в браузере (Chrome, Edge, Яндекс Браузер, Firefox).
2. **Зарегистрируйтесь первым.** Имя и пароль придумайте сами; восстановления пароля нет, запишите его.
3. Создайте сервер (группу) и голосовой канал.
4. Скопируйте приглашение (кнопка с инвайт-кодом рядом с названием сервера) и отправьте друзьям
   в любом мессенджере вместе с адресом сайта. Друзья откроют сайт, зарегистрируются, введут
   код через «Войти по инвайт-коду» и окажутся у вас на сервере.

С телефона тоже работает: просто откройте ссылку в браузере.

## Свой домен

Свой домен (например `mychat.ru`) выглядит приятнее и надёжнее, чем адрес sslip.io.

1. Купите домен у любого регистратора (REG.RU, Timeweb, Beget, RU-CENTER…). Обычно это
   несколько сотен рублей в год.
2. В настройках DNS домена создайте **A-запись**:
   - имя: `@` (сам домен) или поддомен, например `chat` (получится `chat.mychat.ru`);
   - значение: **IP вашего сервера**.
3. Подождите 10–30 минут, пока запись разойдётся по интернету.
4. Подключитесь к серверу и запустите установку с вашим доменом и почтой (почта нужна только
   для писем Let's Encrypt о сертификате, её можно не указывать):
   ```bash
   sudo bash /opt/sozvon/deploy/install.sh --domain chat.mychat.ru --email you@mail.ru
   ```

Все аккаунты, серверы и сообщения сохранятся. Старая ссылка sslip.io перестанет работать,
поэтому отправьте друзьям новую.

Кириллический домен (`.рф`) тоже можно указать как есть: `--domain чат.рф`.

## Обновление

Когда выйдет новая версия Созвона:

```bash
sudo bash /opt/sozvon/deploy/update.sh
```

Скачается свежий код, и службы перезапустятся (на 2–3 секунды все отключатся и сразу подключатся
обратно). Заодно обновление:

- доставит недостающее (ffmpeg — для аватаров и баннеров, yt-dlp и его таймер);
- перерисует конфиг nginx из шаблона (домен и сертификат остаются прежними; если новый конфиг
  не прошёл `nginx -t`, вернётся старый);
- скачает свежее **приложение для ПК** из GitHub Releases (тег `desktop-v*`) в
  `/var/lib/sozvon/downloads/` — друзья скачивают его с вашего сервера на странице
  `https://ваш-адрес/download`, GitHub им не нужен. Если GitHub недоступен, обновление всё равно
  пройдёт; повторить отдельно: `sudo bash /opt/sozvon/deploy/app-release.sh`.

При первом обновлении до версии с ролями база данных обновится сама (у старых серверов появится
роль @everyone с правами по умолчанию). Копия старой базы: `/var/lib/sozvon/db.json.pre-v3-<время>`.

Если в описании обновления сказано, что поменялась установка (например, нужен новый домен), запустите
полную установку ещё раз: `sudo bash /opt/sozvon/deploy/install.sh`.

### Приложение для ПК вручную

```bash
sudo bash /opt/sozvon/deploy/app-release.sh            # последний релиз desktop-v* с GitHub
sudo bash /opt/sozvon/deploy/app-release.sh --force    # скачать заново
sudo bash /opt/sozvon/deploy/app-release.sh --from-dir /root/dist 1.0.0   # свои файлы, без GitHub
```

Если GitHub отвечает «rate limit», задайте токен: `GITHUB_TOKEN=… sudo -E bash …/app-release.sh`.

## Резервная копия

Все данные (пользователи, сообщения, загруженные файлы и музыка) лежат в `/var/lib/sozvon`.
Сделать копию:

```bash
sudo bash /opt/sozvon/deploy/backup.sh
```

Копия сохранится в `/var/backups/sozvon/sozvon-ДАТА.tar.gz`. Чтобы старые копии не занимали
место, оставляйте только несколько последних: `backup.sh --keep 7`.

Хранить копию на том же сервере мало толку. Скачайте её к себе на компьютер: в PowerShell
или Терминале **на своём компьютере** (не на сервере) выполните:

```
scp root@81.200.10.20:/var/backups/sozvon/sozvon-20260101-120000.tar.gz .
```

Файл появится в текущей папке. Храните его как пароль: внутри есть секретные ключи сервера.

Восстановление (например, на новом сервере после установки):

```bash
sudo bash /opt/sozvon/deploy/backup.sh --restore /путь/к/sozvon-ДАТА.tar.gz
```

Текущие данные при этом не удаляются, а переименовываются в `/var/lib/sozvon.before-restore-…`.

**Автоматический бэкап каждую ночь** (необязательно): выполните `sudo crontab -e` и добавьте строку

```
30 4 * * * /bin/bash /opt/sozvon/deploy/backup.sh --keep 7 >/dev/null
```

## Управление

| Что сделать | Команда |
|---|---|
| Перезапустить Созвон | `sudo systemctl restart sozvon` |
| Перезапустить музыкального бота | `sudo systemctl restart sozvon-bot` |
| Посмотреть журнал (выход: Ctrl+C) | `sudo journalctl -u sozvon -f` |
| Журнал бота | `sudo journalctl -u sozvon-bot -f` |
| Состояние служб | `systemctl status sozvon sozvon-bot coturn nginx` |
| Настройки | файл `/etc/sozvon.env` (после правки: `sudo systemctl restart sozvon`) |

Музыку можно загружать прямо через интерфейс (кнопка «Библиотека» в плеере) или ставить ссылкой:
`!play <ссылка YouTube / Spotify / SoundCloud>` — подробно в [MUSIC.md](MUSIC.md). Для ссылок
установщик по умолчанию ставит yt-dlp и ffmpeg и включает их ежедневное автообновление
(отключить — `--no-ytdlp`). Проверить, какие музыкальные источники доступны с вашего сервера:
`sudo bash /opt/sozvon/deploy/music-check.sh`. С российского сервера YouTube часто требует
cookies — см. MUSIC.md; SoundCloud обычно работает сразу.

### Голос через свой TURN (FORCE_RELAY)

По умолчанию весь голос и видео идут **через ваш сервер** (`FORCE_RELAY=1` в `/etc/sozvon.env`).
Так соединение устанавливается у всех, даже за самым строгим NAT мобильного оператора, а участники
не видят IP-адреса друг друга. Цена: трафик идёт через сервер (сколько именно, см. ниже).

Если хотите, чтобы участники по возможности соединялись напрямую (меньше нагрузки на сервер),
запустите установку с `--no-relay`. Свой TURN при этом останется запасным вариантом.

## Сколько тянет

Ориентиры для сервера 1 vCPU / 1–2 ГБ с каналом 100 Мбит/с:

- **Голос:** около **0,1 Мбит/с** на каждый поток. В голосовом канале каждый шлёт звук каждому,
  поэтому при 6 участниках через сервер идёт примерно 6 × 5 × 0,1 ≈ 3 Мбит/с. Это немного.
- **Демонстрация экрана / камера:** **2–4 Мбит/с на каждого зрителя.** Стрим на 5 зрителей
  занимает 10–20 Мбит/с на сервере, а главное, столько же исходящей скорости нужно самому
  стримеру: обычно ограничивает именно его домашний интернет.
- В одном голосовом канале комфортно **до 6–8 человек** (схема «каждый с каждым»). Каналов
  может быть сколько угодно.
- Процессор почти не нагружается: сервер только пересылает пакеты, а не перекодирует их.

## Частые проблемы

**«Не удалось получить сертификат HTTPS»**
- Чаще всего у провайдера закрыт порт 80. У многих есть **облачный файрвол** («Файрвол»,
  «Группы безопасности», «Firewall» в панели). Разрешите там входящие:
  - TCP: **22, 80, 443, 3478, 5349**
  - UDP: **3478** и диапазон **49160–49999**

  Затем снова запустите команду установки.
- Если вы указали свой домен, проверьте A-запись: она должна указывать на IP сервера.
  После изменения подождите 10–30 минут.
- Ошибка про `rate limit` / `too many certificates` означает, что Let's Encrypt временно не выдаёт
  сертификаты для этого адреса (часто бывает с sslip.io). Используйте свой домен или подождите сутки.

**Сайт открывается, но друзья не слышат друг друга / «Подключение…» в голосовом канале**
- Почти всегда закрыты порты TURN. Откройте в облачном файрволе провайдера **UDP 3478** и
  **UDP 49160–49999**, а также **TCP 3478 и 5349**. Файрвол на самом сервере (ufw) установка
  уже настроила.
- Проверьте, что TURN работает: `systemctl status coturn` (должно быть `active (running)`).

**Сайт не открывается совсем**
- Проверьте службы: `systemctl status sozvon nginx`. Перезапустите: `sudo systemctl restart sozvon nginx`.
- Проверьте облачный файрвол (порты 80 и 443).
- Если используете адрес sslip.io и он перестал открываться, причина может быть в самом sslip.io.
  Переходите на свой домен.

**Не работает у друга на мобильном интернете**
- В отдельных регионах мобильные операторы иногда включают режим «белых списков»: открываются
  только разрешённые сайты. В это время ваш сервер с мобильного интернета недоступен, и с этим
  ничего не сделать. По Wi-Fi и домашнему интернету всё работает.

**Забыл пароль от своего аккаунта в Созвоне**
- Восстановления пароля нет. Зарегистрируйтесь заново; если это был владелец сервера-группы,
  создайте новый сервер и пригласите друзей снова.

**Сервер перезагрузили**
- Ничего делать не нужно: Созвон, бот, TURN и nginx запускаются автоматически.

## Безопасность

- Используйте сложный пароль root или вход по SSH-ключу (настраивается в панели провайдера).
- Ubuntu обычно сама ставит обновления безопасности. Иногда полезно обновить всё вручную:
  `sudo apt update && sudo apt upgrade`, затем `sudo reboot`.
- Созвон рассчитан на компанию друзей: модерации и ролей нет. Не публикуйте ссылку-приглашение
  в открытом доступе.

## Удаление

```bash
sudo bash /opt/sozvon/deploy/uninstall.sh          # удалить программу, данные останутся
sudo bash /opt/sozvon/deploy/uninstall.sh --purge  # удалить всё, включая переписку и файлы
```

Скрипт спросит подтверждение. Пакеты nginx/coturn/certbot и правила файрвола остаются.

## Для технически подкованных

Параметры установщика (`install.sh --help`):

| Параметр | Назначение |
|---|---|
| `--domain ДОМЕН` | свой домен (иначе `<ip>.sslip.io`; при повторном запуске берётся прошлый) |
| `--email ПОЧТА` | почта для Let's Encrypt |
| `--ip IPv4` | публичный IP, если автоопределение ошиблось |
| `--relay` / `--no-relay` | `FORCE_RELAY=1/0` |
| `--no-firewall` | не трогать ufw |
| `--no-ytdlp` | не ставить yt-dlp (по умолчанию ставится с таймером автообновления; ffmpeg ставится всегда — он нужен и для аватаров) |
| `--branch ВЕТКА` | ветка git (по умолчанию `main`) |
| `--source КАТАЛОГ` | взять код из локального каталога вместо git |
| `--local-test` | тестовый режим для Docker: без certbot/ufw/определения IP, самоподписанный сертификат, код из `/src` |

Параметры для варианта с `curl | sudo bash` передаются так:
`curl -fsSL …/install.sh | sudo bash -s -- --domain chat.mychat.ru`.

Что и где:

| Путь | Что это |
|---|---|
| `/opt/sozvon` | код (git-клон, владелец root, службы его только читают) |
| `/var/lib/sozvon` | данные (`DATA_DIR`): `db.json`, `uploads/`, `music/`, `media/` (аватары, баннеры, иконки), `downloads/` + `app-release.json` (приложение для ПК), `bot-token.txt` |
| `/etc/sozvon.env` | переменные окружения (chmod 600); `TURN_SECRET` генерируется один раз |
| `/opt/node` | Node.js 22 LTS (если в системе не было Node ≥ 20), ссылки в `/usr/local/bin` |
| `/etc/systemd/system/sozvon{,-bot}.service` | службы (`User=sozvon`, `ProtectSystem=strict`) |
| `/etc/nginx/sites-available/sozvon.conf` | HTTPS-прокси на `127.0.0.1:3000`, WebSocket для `/socket.io/`, загрузка до 110 МБ (`client_max_body_size`); перерисовывается `update.sh` |
| `/etc/turnserver.conf` | coturn: `use-auth-secret`, порты 3478/5349, relay 49160–49999/udp, запрет приватных сетей |
| `/etc/letsencrypt/renewal-hooks/deploy/sozvon-coturn.sh` | после продления копирует сертификат для coturn и перезапускает его |

Сертификат получается через `certbot certonly --webroot` и продлевается системным таймером
`certbot.timer`. Сервер Node работает по HTTP только на `127.0.0.1` (`HTTPS=0`, `TRUST_PROXY=1`),
а TLS снимает nginx. TURN-учётки временные (24 ч, HMAC-SHA1 по схеме TURN REST API) и
выдаются в `/api/config`.
