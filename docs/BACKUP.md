# Резервные копии Astra

Каждую ночь (около 04:30, со случайной задержкой до 20 минут) сервер сам делает резервную копию
всех данных и настроек. Ничего включать не нужно: таймер `sozvon-backup.timer` ставят
`deploy/install.sh` и `deploy/update.sh`.

| Что сделать | Команда (на сервере) |
|---|---|
| Сделать копию прямо сейчас | `sudo bash /opt/sozvon/deploy/backup.sh now` |
| Посмотреть копии и последний ночной запуск | `sudo bash /opt/sozvon/deploy/backup.sh list` |
| Восстановить из копии | `sudo bash /opt/sozvon/deploy/backup.sh restore ФАЙЛ` |
| Включить отправку копий в свой Telegram-бот | `sudo bash /opt/sozvon/deploy/backup.sh setup` |
| Проверить связь с ботом | `sudo bash /opt/sozvon/deploy/backup.sh telegram-test` |
| Журнал ночных копий | `journalctl -u sozvon-backup -n 50 --no-pager` |

## Что попадает в копию

Копия лежит в `/var/backups/sozvon/astra-ГГГГММДД-ЧЧММ.tar.zst` (или `.tar.gz`, если на сервере нет
`zstd`). Права у файла — 600, владелец root: никто, кроме root, его не прочитает.

Внутри:

- `data/` — всё из `/var/lib/sozvon`, что нельзя восстановить само:
  база `db.json` (пользователи, серверы, каналы, сообщения, роли), вложения `uploads/`,
  аватары, баннеры и иконки `media/`, музыкальная библиотека `music/` (загруженные и скачанные по ссылкам треки),
  ключи push-уведомлений `vapid.json`, токен бота `bot-token.txt`, ключ шифрования 2FA `totp-key`, сертификаты `certs/`;
- `env/sozvon.env` — настройки из `/etc/sozvon.env` (пароль TURN, токены и т. п.);
- `BACKUP-INFO.txt` — когда и откуда сделана копия.

Не попадает (сервер восстановит это сам): кэш yt-dlp и прочие кэши (`.cache/`), файлы приложения
для ПК (`downloads/` — их раз в час скачивает таймер `sozvon-app-release`), программа cloudflared (`bin/`),
недокачанные/временные файлы (`music/.upload-*`, `music/.dl-*`, `media/.tmp`, `*.tmp`).

Если музыкальная библиотека очень большая и в копии не нужна, добавьте в `/etc/sozvon.env` строку
`BACKUP_MUSIC=0`. Учтите: после восстановления такой копии треки придётся загрузить заново.

**Копию можно делать на работающем сервере.** База `db.json` записывается атомарно (сначала во
временный файл, потом мгновенная замена), поэтому её копия всегда целая. Скрипт копирует базу
первой, а уже потом файлы — все вложения и треки, на которые ссылается база, в копию попадут.

## Сколько копий хранится

Самая свежая копия за каждый из последних 7 дней и ещё по одной копии за 4 предыдущие недели —
то есть можно откатиться примерно на месяц назад. Если сделать копию вручную, она заменит
ночную копию того же дня. Изменить число копий — в `/etc/sozvon.env`:

```
BACKUP_KEEP_DAILY=7
BACKUP_KEEP_WEEKLY=4
```

`backup.sh list` показывает копии, их размер, общий объём и результат последнего ночного запуска.
Итог каждого запуска (успех или ошибка, без секретов) также пишется в `/var/lib/sozvon-state/backup-status.json` —
по нему сервер следит, что копии делаются (копия старше 36 ч или неудачная — повод проверить).
Копии в `/var/backups/sozvon` лежат на **том же** сервере: от ошибки или поломки базы они спасут,
а от потери самого сервера — нет. Поэтому храните копию ещё где-то: скачайте к себе или включите Telegram.

## Скачать копию к себе на компьютер

В PowerShell или Терминале **на своём компьютере** (не на сервере):

```
scp root@81.200.10.20:/var/backups/sozvon/astra-20260101-0430.tar.zst .
```

(вместо `81.200.10.20` — IP вашего сервера, имя файла — из `backup.sh list`). Файл не зашифрован и
содержит секреты сервера — храните его как пароль.

## Копия в свой Telegram-бот (по желанию)

Сервер может каждую ночь отправлять копию **вашему собственному** боту в Telegram. Копия перед отправкой
шифруется на сервере (AES-256, ключ из вашего пароля), в Telegram попадает только зашифрованный файл.
Других сторонних сервисов скрипт не использует.

1. В Telegram откройте **@BotFather** → `/newbot` → придумайте имя → получите токен вида `123456:ABC…`.
2. Откройте своего нового бота и нажмите **Start** (или напишите ему любое сообщение).
3. На сервере выполните `sudo bash /opt/sozvon/deploy/backup.sh setup` и введите токен, chat id
   (можно оставить пустым — скрипт найдёт его сам по вашему сообщению боту) и пароль шифрования
   (не меньше 12 символов, ввод скрыт). Настройки запишутся в `/etc/sozvon.env` (права 600):

   ```
   BACKUP_TELEGRAM_TOKEN='123456:ABC…'
   BACKUP_TELEGRAM_CHAT_ID='123456789'
   BACKUP_PASSPHRASE='ваш пароль'
   ```

4. Бот пришлёт тестовое сообщение. Следующей ночью придёт первая копия (или сразу: `backup.sh now`).

**Запишите пароль в менеджер паролей.** Без него копию из Telegram не расшифровать — ни вам, ни кому-либо ещё.
Без `BACKUP_PASSPHRASE` копии в Telegram не отправляются вообще.

Бот может принять файл не больше 50 МБ, поэтому копия больше 45 МБ уходит частями
`astra-….tar.zst.enc.part00`, `.part01`, … Если частей получилось бы больше 20 (≈ 900 МБ),
копия в Telegram не отправляется — в журнале будет предупреждение, а `systemctl status sozvon-backup`
покажет ошибку; локальная копия при этом всё равно сделана. Обычно разрастается музыка — включите
`BACKUP_MUSIC=0` или скачивайте копии через `scp`.

Отключить отправку: удалите строки `BACKUP_TELEGRAM_*` из `/etc/sozvon.env`.

### Как расшифровать копию из Telegram

Скачайте файлы из чата с ботом в одну папку. Если частей несколько — сначала склейте их
(в Linux/macOS; части по порядку):

```bash
cat astra-20260101-0430.tar.zst.enc.part* > astra-20260101-0430.tar.zst.enc
```

В Windows (cmd): `copy /b astra-20260101-0430.tar.zst.enc.part00+astra-20260101-0430.tar.zst.enc.part01 astra-20260101-0430.tar.zst.enc`

Расшифровать (спросит пароль):

```bash
openssl enc -d -aes-256-cbc -pbkdf2 -iter 200000 -in astra-20260101-0430.tar.zst.enc -out astra-20260101-0430.tar.zst
```

Посмотреть содержимое: `tar -I zstd -tvf astra-20260101-0430.tar.zst` (для `.tar.gz` — `tar -tzvf …`).

Расшифровывать вручную не обязательно: `restore` сам понимает `.enc` и `.enc.part00` (см. ниже).

## Восстановление

Например, после поломки или на новом сервере (сначала поставьте Astra обычным `install.sh`).
Загрузите копию на сервер (`scp astra-….tar.zst root@IP:/root/`) и выполните:

```bash
sudo bash /opt/sozvon/deploy/backup.sh restore /root/astra-20260101-0430.tar.zst
```

Можно указать и просто имя копии из `/var/backups/sozvon`, зашифрованный файл `….enc` или первую часть
`….enc.part00` (остальные части должны лежать рядом) — скрипт спросит пароль или возьмёт `BACKUP_PASSPHRASE`.

Что делает `restore`:

1. Проверяет архив и показывает, когда сделана копия. Спрашивает подтверждение — нужно написать «да».
2. Спрашивает, восстанавливать ли настройки `/etc/sozvon.env` из копии (по умолчанию — нет;
   на новом сервере с другим доменом/IP обычно не нужно). Прежний файл сохраняется как `/etc/sozvon.env.bak-…`.
3. Останавливает `sozvon-bot` и `sozvon`.
4. Переименовывает текущие данные в `/var/lib/sozvon.bak-ГГГГММДД-ЧЧММСС` (ничего не удаляется).
5. Распаковывает копию в `/var/lib/sozvon`, отдаёт файлы пользователю `sozvon`.
6. Запускает службы и печатает команды для проверки:

```bash
systemctl status sozvon sozvon-bot --no-pager
journalctl -u sozvon -n 50 --no-pager
curl -fsS http://127.0.0.1:3000/api/config && echo OK
```

Если всё работает — старые данные можно удалить: `rm -rf /var/lib/sozvon.bak-…`. Если нет — команда
для отката на прежние данные напечатана в конце вывода `restore`.

Копии старого формата (`sozvon-ДАТА.tar.gz` от прежнего `backup.sh`) тоже восстанавливаются.

## Для тестов и нестандартных установок

Скрипт берёт пути из переменных окружения: `DATA_DIR`, `SOZVON_ENV_FILE`, `BACKUP_DIR`, `APP_USER`,
`BACKUP_SERVICES` (по умолчанию `sozvon-bot sozvon`); `systemctl` ищется в `PATH`.
`BACKUP_COMPRESS=gzip` — без zstd. `BACKUP_TELEGRAM_API` — другой адрес Bot API (в тестах — локальный сервер),
`BACKUP_TELEGRAM_PART_SIZE` (по умолчанию `45M`), `BACKUP_TELEGRAM_MAX_PARTS` (20).
`BACKUP_ASSUME_YES=1` и `BACKUP_RESTORE_ENV=y|n` — восстановление без вопросов.
Тесты: `tests/v13-backup.spec.js`.
