# Безопасность аккаунтов

## Пароли и защита от перебора

- Пароли хранятся только как bcrypt-хэш (cost 10).
- Вход: не больше 10 неудачных попыток в один аккаунт с одного адреса и 30 с адреса за 10 минут,
  регистрация — 10 с адреса за час (`server/rate-limit.js`). Запросы с самого сервера (127.0.0.1) не
  ограничиваются, если сервер работает не за прокси; за nginx включите `TRUST_PROXY=1`.
- Смена пароля завершает все остальные сеансы.

## Двухфакторная защита (2FA, TOTP)

Включается в «Настройки → Моя учётная запись → Двухфакторная защита». Работает в браузере, PWA
и приложении для ПК (у них один клиент). Сторонние сервисы не нужны: QR-код рисуется прямо в браузере
(`public/js/qr.js`), коды считаются по времени (RFC 6238) приложением на телефоне — Google Authenticator,
Aegis, 2FAS, 1Password, Bitwarden и т. п.

### Как это работает для пользователя

1. **Подключение**: текущий пароль → QR-код, секретный ключ текстом и ссылка `otpauth://`
   (издатель «Astra», аккаунт — имя пользователя) → 6-значный код из приложения → защита включена и
   показываются **10 одноразовых кодов восстановления** (их можно скачать `.txt` или скопировать; больше
   они не показываются). Уже открытые сеансы не завершаются — для этого есть «Выйти на других устройствах».
2. **Вход**: имя и пароль → второй шаг «Двухфакторная защита» → код из приложения или код
   восстановления. На второй шаг даётся 5 минут.
3. **Чувствительные действия** требуют свежий код (или код восстановления): смена пароля, отключение 2FA,
   новые коды восстановления (плюс текущий пароль).
4. **Потеря телефона**: войти кодом восстановления (каждый — один раз), затем отключить 2FA или
   подключить заново. Если потеряны и коды — администратор сервера может отключить 2FA вручную
   (остановить сервер, в `data/db.json` у пользователя выставить `"totpEnabled": false`, запустить).

### Параметры

| | |
|---|---|
| Алгоритм | TOTP (RFC 6238) на HMAC-SHA1, шаг 30 с, 6 цифр |
| Окно | ±1 шаг (часы телефона могут расходиться на ±30 с) |
| Секрет | 160 бит (`crypto.randomBytes(20)`), base32 |
| Повтор кода | запоминается последний принятый шаг (`totpLastStep`): тот же или более старый код не принимается |
| Коды восстановления | 10 штук вида `xxxxx-xxxxx` (≈ 49 бит), хранятся только HMAC-SHA256-хэши, каждый одноразовый |
| Второй шаг входа | одноразовый токен (256 бит), 5 минут, привязан к пользователю и его текущему паролю; после 3 неверных кодов — заново с паролем |
| Блокировка аккаунта | 5 неверных кодов за 15 минут (с любых адресов, при входе и в настройках) → 15 минут коды не принимаются (429) |
| Блокировка адреса | 20 неверных кодов с одного адреса за 15 минут → 429 (учитывает `TRUST_PROXY`) |
| Пароль в настройках 2FA | 10 неверных за 15 минут → 429 |
| Боты | включить 2FA нельзя; вход бота по токену не меняется |

Ошибки намеренно общие: «Неверный код», «Время на ввод кода истекло. Войдите заново.» — по ним нельзя
понять, какой именно фактор не подошёл. До проверки пароля сервер не сообщает, включена ли у аккаунта 2FA.

### Хранение

Поля пользователя в `data/db.json`:

- `totpEnabled` — `true`/`false`; это единственное, что видит клиент, и только сам владелец
  (`GET /api/me`, событие `user:updated` своему сеансу). Другим участникам флаг не отдаётся;
- `totpSecret` — секрет, зашифрованный **AES-256-GCM** (формат `v1.<base64url(iv|tag|шифртекст)>`,
  AAD — id пользователя, т. е. запись нельзя пересадить другому пользователю);
- `totpLastStep`, `totpRecovery` (хэши), `totpEnabledAt`.

Ключи выводятся через HKDF-SHA256 из **`data/totp-key`** — 32 случайных байта, права `600`, файл создаётся
при первом обращении к 2FA. Он входит в ночные резервные копии (`deploy/backup.sh` копирует весь `data/`).
**Без этого файла коды 2FA и коды восстановления перестанут подходить у всех** — храните его вместе с `db.json`.
Если файл пропал, а у кого-то включена 2FA, сервер пишет об этом в лог при старте использования.

### REST API

| Запрос | Тело | Ответ |
|---|---|---|
| `POST /api/login` | `{ username, password }` | без 2FA — `{ token, user }`; с 2FA — `{ twoFactor: true, challenge, methods }` |
| `POST /api/login/2fa` | `{ challenge, code }` | `{ token, user }` |
| `GET /api/me/2fa` | — | `{ enabled, recoveryCodesLeft, enabledAt }` |
| `POST /api/me/2fa/setup` | `{ password }` | `{ secret, uri, issuer, account, digits, period }` |
| `POST /api/me/2fa/enable` | `{ code }` | `{ recoveryCodes, user }` |
| `POST /api/me/2fa/disable` | `{ password, code }` | `{ user }` |
| `POST /api/me/2fa/recovery-codes` | `{ password, code }` | `{ recoveryCodes }` |
| `POST /api/me/password` | `{ oldPassword, newPassword, code? }` | `code` обязателен при включённой 2FA |
| `POST /api/me/sessions/revoke-others` | — | `{ revoked }` — «Выйти на других устройствах» |

Ошибки второго фактора: `{ error, code }`, где `code` — `totp_required` (403, код не передан),
`totp_invalid` (неверный), `totp_locked` (429, заголовок `Retry-After`), `challenge_invalid` (401).

### Для разработчиков: проверка 2FA в других модулях

```js
import { verifyUserTotp, requireRecent2FA } from './auth.js'; // или из './totp.js'

// true — код верен (и «израсходован»: повтор будет отклонён); false — неверен / 2FA выключена / бот / блокировка.
// Неудачи учитываются в блокировке аккаунта. { allowRecovery: true } — принимать и код восстановления.
verifyUserTotp(user, code);

// Для обработчика Express с requireAuth: null — у пользователя 2FA выключена (ничего не требуется),
// 'totp' | 'recovery' — код принят; иначе бросает HttpError (403 totp_required / totp_invalid, 429 totp_locked),
// учитывая лимиты по аккаунту и по адресу. По умолчанию код восстановления тоже принимается
// ({ allowRecovery: false } — только код из приложения).
requireRecent2FA(req, req.body?.code);
```

Требовать 2FA для роли (например, администраторов) — проверять `user.totpEnabled === true`.

коды восстановления, блокировки, отключение, смена пароля, отсутствие утечек, UI на ПК и узком экране).
