# Безопасность аккаунтов

## Пароли и защита от перебора

- Пароли хранятся только как bcrypt-хэш (cost 10).
- Вход: не больше 10 неудачных попыток в один аккаунт с одного адреса и 30 с адреса за 10 минут,
  регистрация — 10 с адреса за час (`server/rate-limit.js`). Запросы с самого сервера (127.0.0.1) не
  ограничиваются, если сервер работает не за прокси; за nginx включите `TRUST_PROXY=1`.
- Смена пароля завершает все остальные сеансы.

## Двухфакторная защита (2FA)

Включается в «Настройки → Моя учётная запись → Двухфакторная защита». Работает в браузере, PWA
и приложении для ПК (у них один клиент). Два способа — можно включить один или оба, при входе подходит любой:

- **Приложение-аутентификатор (TOTP)** — сторонние сервисы не нужны: QR-код рисуется прямо в браузере
  (`public/js/qr.js`), коды считаются по времени (RFC 6238) приложением на телефоне — Google Authenticator,
  Яндекс Ключ, Aegis, 2FAS, 1Password, Bitwarden и т. п.
- **Telegram** — для тех, кто не хочет ставить приложение: код входа и кнопки «✅ Это я» / «⛔ Это не я»
  присылает Telegram-бот вашего сервера (см. [ниже](#вход-через-telegram)).

Коды восстановления — **один набор на аккаунт** для любого способа: создаются при включении первого способа
и удаляются, когда выключен последний.

### Как это работает для пользователя

1. **Подключение**: текущий пароль → QR-код, секретный ключ текстом и ссылка `otpauth://`
   (издатель «Astra», аккаунт — имя пользователя) → 6-значный код из приложения → защита включена и
   показываются **10 одноразовых кодов восстановления** (их можно скачать `.txt` или скопировать; больше
   они не показываются). Уже открытые сеансы не завершаются — для этого есть «Выйти на других устройствах».
2. **Вход**: имя и пароль → второй шаг «Двухфакторная защита» → код из приложения или код
   восстановления. На второй шаг даётся 5 минут.
3. **Чувствительные действия** требуют свежий код (или код восстановления): смена пароля, отключение 2FA,
   новые коды восстановления (плюс текущий пароль).
4. **Потеря телефона**: войти кодом восстановления (каждый — один раз), затем отключить 2FA или
   подключить заново. Если потеряны и коды — владелец сервера может отключить 2FA вручную
   (остановить сервер, в `data/db.json` у пользователя выставить `"totpEnabled": false` и `"tg2fa": false`, запустить).

### Параметры

| | |
|---|---|
| Алгоритм | TOTP (RFC 6238) на HMAC-SHA1, шаг 30 с, 6 цифр |
| Окно | ±1 шаг (часы телефона могут расходиться на ±30 с) |
| Секрет | 160 бит (`crypto.randomBytes(20)`), base32 |
| Повтор кода | запоминается последний принятый шаг (`totpLastStep`): тот же или более старый код не принимается |
| Коды восстановления | 10 штук вида `xxxxx-xxxxx` (≈ 49 бит), хранятся только HMAC-SHA256-хэши, каждый одноразовый |
| Второй шаг входа | одноразовый токен (256 бит), 5 минут, привязан к пользователю и его текущему паролю; после 3 неверных кодов — заново с паролем |
| Блокировка аккаунта | 5 неверных кодов за 15 минут (с любых адресов, при входе и в настройках) → 15 минут коды не принимаются (429) |
| Блокировка адреса | 20 неверных кодов с одного адреса за 15 минут → 429 (учитывает `TRUST_PROXY`) |
| Пароль в настройках 2FA | 10 неверных за 15 минут → 429 |
| Боты | включить 2FA нельзя; вход бота по токену не меняется |

Ошибки намеренно общие: «Неверный код», «Время на ввод кода истекло. Войдите заново.» — по ним нельзя
понять, какой именно фактор не подошёл. До проверки пароля сервер не сообщает, включена ли у аккаунта 2FA.

### Хранение

Поля пользователя в `data/db.json`:

- `totpEnabled` — `true`/`false`; это единственное, что видит клиент, и только сам владелец
  (`GET /api/me`, событие `user:updated` своему сеансу). Другим участникам флаг не отдаётся;
- `totpSecret` — секрет, зашифрованный **AES-256-GCM** (формат `v1.<base64url(iv|tag|шифртекст)>`,
  AAD — id пользователя, т. е. запись нельзя пересадить другому пользователю);
- `totpLastStep`, `totpRecovery` (хэши), `totpEnabledAt`.

Ключи выводятся через HKDF-SHA256 из **`data/totp-key`** — 32 случайных байта, права `600`, файл создаётся
при первом обращении к 2FA. Он входит в ночные резервные копии (`deploy/backup.sh` копирует весь `data/`).
**Без этого файла коды 2FA и коды восстановления перестанут подходить у всех** — храните его вместе с `db.json`.
Если файл пропал, а у кого-то включена 2FA, сервер пишет об этом в лог при старте использования.

### REST API

| Запрос | Тело | Ответ |
|---|---|---|
| `POST /api/login` | `{ username, password }` | без 2FA — `{ token, user }`; с 2FA — `{ twoFactor: true, challenge, methods }` |
| `POST /api/login/2fa` | `{ challenge, code }` | `{ token, user }` |
| `GET /api/me/2fa` | — | `{ enabled, totpEnabled, recoveryCodesLeft, enabledAt, telegram }` |
| `POST /api/me/2fa/setup` | `{ password }` | `{ secret, uri, issuer, account, digits, period }` |
| `POST /api/me/2fa/enable` | `{ code }` | `{ recoveryCodes, user }` (`recoveryCodes: null, recoveryKept: true`, если уже включён Telegram) |
| `POST /api/me/2fa/disable` | `{ password, code }` | `{ user }` |
| `POST /api/me/2fa/recovery-codes` | `{ password, code }` | `{ recoveryCodes }` |
| `POST /api/me/password` | `{ oldPassword, newPassword, code? }` | `code` обязателен при включённой 2FA |
| `POST /api/me/sessions/revoke-others` | — | `{ revoked }` — «Выйти на других устройствах» |

Ошибки второго фактора: `{ error, code }`, где `code` — `totp_required` (403, код не передан),
`totp_invalid` (неверный), `totp_locked` (429, заголовок `Retry-After`), `challenge_invalid` (401).

### Для разработчиков: проверка 2FA в других модулях

```js
import { verifyUserTotp, requireRecent2FA } from './auth.js'; // или из './totp.js'

// true — код верен (и «израсходован»: повтор будет отклонён); false — неверен / 2FA выключена / бот / блокировка.
// Неудачи учитываются в блокировке аккаунта. { allowRecovery: true } — принимать и код восстановления.
verifyUserTotp(user, code);

// Для обработчика Express с requireAuth: null — у пользователя 2FA выключена (ничего не требуется),
// 'totp' | 'recovery' — код принят; иначе бросает HttpError (403 totp_required / totp_invalid, 429 totp_locked),
// учитывая лимиты по аккаунту и по адресу. По умолчанию код восстановления тоже принимается
// ({ allowRecovery: false } — только код из приложения).
requireRecent2FA(req, req.body?.code);
```

Требовать 2FA для роли — проверять `has2FA(user)` из `server/totp.js` (приложение или Telegram) либо
`user.totpEnabled === true`, если нужно именно приложение. `requireRecent2FA` принимает и код из Telegram
«для действия» (`{ tg: null }` — не принимать).

Тесты: `tests/v20-2fa.spec.js` (векторы RFC 6238/4226, QR-матрица, подключение, вход, повтор,
коды восстановления, блокировки, отключение, смена пароля, отсутствие утечек, UI на ПК и узком экране).

## Вход через Telegram

Второй фактор через Telegram-бота владельца сервера (`server/tg2fa.js`, клиент Bot API — `server/telegram.js`).
Отдельный бот не обязателен: используется тот же бот, что для резервных копий.

### Настройка (владелец сервера)

В `/etc/sozvon.env` должен быть токен бота — `TELEGRAM_BOT_TOKEN`, а если его нет, берётся `ALERT_TELEGRAM_TOKEN`,
затем `BACKUP_TELEGRAM_TOKEN` (его задаёт `sudo bash deploy/backup.sh setup`). После изменения — перезапуск
(`sudo systemctl restart sozvon`). Без токена способ «Telegram» в настройках просто не показывается.

Telegram из РФ часто недоступен напрямую: сервер сначала обращается к Bot API напрямую, а при сетевой ошибке —
через VPN-прокси `SPOTIFY_PROXY` (`deploy/vpn-proxy.sh`, туннель HTTP CONNECT) и следующие 10 минут сразу через
него. `TELEGRAM_PROXY=http://…` — всегда через указанный прокси, `TELEGRAM_PROXY=off` — только напрямую.
Адрес Bot API можно переопределить (`TELEGRAM_API`, иначе `ALERT_TELEGRAM_API` / `BACKUP_TELEGRAM_API`) — для тестов.

Входящие сообщения сервер получает **опросом `getUpdates`** (long polling, 25 с; вебхук не нужен и не ставится).
Опрос идёт постоянно, пока задан токен: через бота работают меню, ответы на уведомления, вход без пароля
(см. [TELEGRAM.md](TELEGRAM.md)). Второй читатель `getUpdates` того же бота мешал бы серверу (Telegram отвечает
409), поэтому `sudo bash deploy/backup.sh setup` при работающем сервере **не вызывает `getUpdates`**: chat id он
спрашивает у самого сервера через локальный unix-сокет `data/admin.sock` (права 600, токен в
`data/admin-control.token` — подключиться может только root и сам сервис): сервер помнит чаты, отправившие боту
`/start` за последние 15 минут, и отдаёт их, только если `setup` настраивает того же бота (сравниваются первые
16 знаков SHA-256 токена, сам токен не передаётся). Когда служба остановлена (или бот другой) — как раньше,
`getUpdates`. Узнать chat id отдельно: `sudo bash deploy/backup.sh telegram-chat-id`. `TELEGRAM_POLLING=0` —
старое поведение (опрос только пока ждём привязку/подтверждение). Смещение хранится в
`data/telegram-offset.json` (плюс последние `update_id` в памяти — повтор не исполняется), сетевые ошибки и 409 —
повтор с нарастающей паузой до 60 с.

### Как это работает для пользователя

1. **Привязка**: «Двухфакторная защита» → «Telegram» → текущий пароль → одноразовая ссылка
   `https://t.me/<бот>?start=<токен>` и её QR-код (действует 10 минут) → в боте «Запустить» (Start).
   Бот отвечает «Аккаунт Astra «имя» привязан…», страница настроек обновляется сама и показывает коды
   восстановления (если до этого 2FA не было). В настройках виден привязанный Telegram (имя/@ник) —
   если там чужой аккаунт, сразу отвяжите его.
2. **Вход**: после верного пароля бот присылает «🔐 Вход в Astra», 6-значный код, устройство (браузер и ОС)
   и IP с маской (`89.108.*.*`) и кнопки **«✅ Это я»** / **«⛔ Это не я»**. Можно нажать «Это я» — экран входа
   завершит вход сам, — или ввести код. После использования сообщение меняется на «✅ Вход подтверждён»,
   «⛔ Вход отклонён» или «⌛ Код истёк». «Отправить код ещё раз» — не чаще раза в 30 секунд и не больше
   5 раз за 15 минут. Если Telegram недоступен с сервера, экран входа говорит об этом и предлагает код из
   приложения или код восстановления.
3. **«⛔ Это не я»**: попытка входа отменяется, вход по коду из Telegram для аккаунта приостанавливается на
   15 минут (приложение и коды восстановления продолжают работать), бот советует сменить пароль и выйти на
   других устройствах, событие записывается в журнал сервера.
4. **Отвязка и другие чувствительные действия** (смена пароля, новые коды восстановления): пароль + код —
   кнопка «Прислать код в Telegram» присылает код «для действия» (без кнопок), подходит и код из приложения
   или код восстановления.
5. **Рекомендация**: включите в Telegram «Облачный пароль» (Настройки → Конфиденциальность → Облачный пароль) —
   иначе тот, кто перевыпустит вашу SIM-карту, получит и Telegram, и коды. Бот включить его не может.

### Параметры и защита

| | |
|---|---|
| Ссылка привязки | 192 бита (`randomBytes(24)`), 10 минут, одноразовая, в памяти только SHA-256; одна ссылка на пользователя |
| Код | 6 цифр (`crypto.randomInt`), 5 минут, одноразовый, в памяти только HMAC-SHA256 (ключ процесса); привязан к своему запросу: шагу входа, сеансу или «действию в настройках» — чужой код не подойдёт |
| Кнопки | `callback_data` — непрозрачный случайный id запроса (128 бит); нажатие принимается только из привязанного личного чата, совпадающего с чатом, куда ушёл код |
| Неверные коды | общий счётчик 2FA: 5 за 15 минут → блокировка аккаунта на 15 минут, 20 с адреса → 429; после 3 неверных кодов шаг входа сгорает |
| Отправка | 1 раз в 30 с и 5 раз за 15 минут на аккаунт (`429 tg_resend_limited`, `Retry-After`) |
| Чужие чаты | непривязанному чату бот отвечает только на `/start`, `/menu`, `/help` — подсказкой, как привязать аккаунт; прочее игнорируется. Только личные чаты; не больше 40 обновлений в минуту с чата |
| Токен бота | не попадает в журналы, ответы API и тексты ошибок |

Поля пользователя в `data/db.json`: `tg2fa`, `tgChatId` (chat id — **никому не отдаётся**, ни другим участникам,
ни самому владельцу), `tgLinkedAt`, `tgName` (имя в Telegram — видит только сам владелец), `tgLockUntil`,
`tgLogin` («Вход без пароля через Telegram»), `tgNotify` (что пересылать в Telegram, [TELEGRAM.md](TELEGRAM.md)).
Клиенту — только флаг `tg2faEnabled` и только самому владельцу.

### REST API (Telegram)

| Запрос | Тело | Ответ |
|---|---|---|
| `POST /api/login` | `{ username, password }` | с Telegram: `{ twoFactor, challenge, methods: [..., 'telegram', ...], telegram: { state, resendIn } }` |
| `POST /api/login/2fa/status` | `{ challenge }` | `{ token, user }` после «Это я»; иначе `{ pending, telegram }`; `401 challenge_denied` после «Это не я» |
| `POST /api/login/2fa/resend` | `{ challenge }` | `{ telegram }`; `429 tg_resend_limited` / `tg_locked` |
| `POST /api/me/2fa/telegram/link` | `{ password, passwordless? }` (вход без пароля, по умолчанию `true`) | `{ link, bot, expiresAt }` |
| `GET /api/me/2fa/telegram/link` | — | `{ linked, pending, recoveryCodes? }` (коды — один раз) |
| `DELETE /api/me/2fa/telegram/link` | — | отменить ссылку |
| `POST /api/me/2fa/telegram/code` | — | `{ telegram }` — код «для действия» |
| `POST /api/me/2fa/telegram/unlink` | `{ password, code }` | `{ user }` |

`GET /api/me/2fa` дополнительно возвращает `totpEnabled` и `telegram: { available, enabled, linkedAt, account, lockedFor }`;
`enabled` — включён ли хотя бы один способ. `state`: `sending`, `sent`, `failed` (Telegram недоступен),
`locked`, `limited`, `unavailable`, `none`.

Тесты: `tests/v23-tg-2fa.spec.js` (фейковый Bot API и VPN-прокси: привязка, неверная и просроченная ссылка,
вход кодом и кнопкой, «Это не я», лимиты отправки, отвязка, путь через прокси, отсутствие утечек токена и chat id).

## Сброс пароля и вход без пароля через Telegram

Для пользователей с привязанным Telegram (`server/pwreset.js`, `server/tg2fa.js`, REST — `server/tg-routes.js`;
как этим пользоваться — [TELEGRAM.md](TELEGRAM.md)).

**Сброс пароля** («Забыли пароль?» на экране входа или «🔑 Сбросить пароль» в меню бота):

| | |
|---|---|
| Ответ на запрос | всегда одинаковый — не видно, есть ли такой пользователь и привязан ли у него Telegram |
| Ссылка | `<PUBLIC_URL>/reset-password#t=<токен>`: 256 бит, 15 минут, одноразовая, в памяти только SHA-256; новая ссылка отменяет прежнюю; кнопка «⛔ Это не я» отменяет ссылку |
| Где токен | во фрагменте `#t=…` — браузер не отправляет его при открытии страницы (нет в журналах nginx и `Referer`), страница сразу убирает его из адреса; на сервер он уходит только POST-запросом |
| Адрес ссылки | только из `PUBLIC_URL` (или ссылки туннеля), не из заголовка `Host` запроса — подделанный `Host` не уведёт ссылку на чужой сайт. Без `PUBLIC_URL` ссылки не отправляются |
| Второй фактор | если включено приложение-аутентификатор — нужен ещё код из него или код восстановления (коды из Telegram не принимаются: одного Telegram мало) |
| После смены | завершаются **все** сеансы и сокеты, бот сообщает «✅ Пароль изменён», событие — в журнале сервера |
| Лимиты | 5 запросов с адреса за 15 минут (`429`); на аккаунт — общий лимит сообщений бота (раз в 30 с, 5 за 15 минут); 20 неверных ссылок с адреса за 15 минут; не отправляется, пока действует блокировка после «Это не я» |

**Вход без пароля** («Войти через Telegram» → имя → кнопка «✅ Войти» в боте):

| | |
|---|---|
| Включение | только по желанию пользователя: галочка при привязке (по умолчанию включена), переключатель в «Уведомления» → «Telegram». Включить — только в Astra с вводом пароля; в боте его можно только **выключить** (иначе доступ к одному чату превращался бы в доступ к аккаунту) |
| Ответ на запрос | всегда одинаковый (`{ challenge, expiresAt }`); для несуществующих и выключенных аккаунтов токен просто никогда не подтверждается |
| Подтверждение | кнопкой из привязанного личного чата (как «Это я»); 5 минут, одноразово; устройство и IP с маской в сообщении |
| Приложение-аутентификатор | если включено, после «✅ Войти» всё равно нужен код из него (или код восстановления) — обычный второй шаг `/api/login/2fa` |
| «⛔ Это не я» | запрос отменяется, вход по Telegram (коды и без пароля) приостанавливается на 15 минут, событие — в журнале |
| Лимиты | 10 запросов с адреса за 10 минут; на аккаунт — общий лимит сообщений бота; заблокированный аккаунт не входит |

| Запрос | Тело | Ответ |
|---|---|---|
| `POST /api/password-reset/request` | `{ username }` | `{ ok, message }` — всегда одинаковый |
| `POST /api/password-reset/check` | `{ token }` | `{ valid, username, needCode }`; `400 reset_invalid` |
| `POST /api/password-reset/complete` | `{ token, password, code? }` | `{ ok }`; `403 totp_required` / `totp_invalid` |
| `POST /api/login/telegram` | `{ username }` | `{ challenge, expiresAt }` |
| `POST /api/login/telegram/status` | `{ challenge }` | `{ pending }` · `{ token, user }` · `{ twoFactor, challenge, methods }`; `401 challenge_denied` / `challenge_invalid` |
| `GET /api/me/telegram` | — | `{ available, linked, account, bot, notify, passwordless }` |

(`SEND_MESSAGES`), общий сервер для ЛС, длина, лимит частоты; только текст. Ответ принимается, только если
уведомление пришло в этот же привязанный чат и ему не больше 3 суток.
